# Claude в этом проекте — карта на одну страницу

Здесь — что где лежит и кого звать. Подробности:

- [GUIDE.md](GUIDE.md) — руководство: глоссарий, агенты, хуки, права, сценарии, промпты.
- [COMMANDS.md](COMMANDS.md) — справочник slash-команд: встроенные, свои скиллы, команды проекта.
- [CLAUDE.md](../../CLAUDE.md) — правила проекта, которые Claude читает сам.

## С чего начать

1. **Прочитайте корневой `CLAUDE.md`** (5 минут). Это правила, которые Claude знает всегда.
2. **Откройте [GUIDE.md](GUIDE.md)**, разделы 0 (глоссарий) и 1 (как устроен Claude Code).
3. **Запустите `claude` в корне репозитория** на своей ветке (`feat/…`, `fix/…`, `chore/…`, `docs/…`) и посмотрите, что загружено: `/skills`, `/agents`, `/hooks`, `/mcp`.
4. **Попробуйте безопасную задачу:** `/verify` или «Используй агента `code-reviewer`: проверь ветку относительно `main`». Сверьте поведение с [COMMANDS.md](COMMANDS.md), раздел 4.1.
5. **Перед реальной задачей** выберите сценарий из [GUIDE.md, раздел 10](GUIDE.md#10-сценарии-end-to-end): `/new-feature`, `/new-spec` или `/db-migration`. Для новой фичи сначала прочитайте [раздел 10.0](GUIDE.md#100-как-согласуется-фича-от-идеи-до-утверждённой-спеки-и-макета).

## Что где лежит

| Сущность | Файлы | Что это |
|---|---|---|
| Память проекта | `CLAUDE.md`, `backend/CLAUDE.md`, `frontend/AGENTS.md` | Правила и контекст, которые Claude читает сам |
| Правила по путям | `.claude/rules/*.md` | Подгружаются, когда Claude работает с подходящими файлами |
| Агенты | `.claude/agents/*.md` | 14 «специалистов» со своим контекстом, инструментами и моделью (все на `sonnet`) |
| Скиллы (команды) | `.claude/skills/*/SKILL.md` | 9 повторяемых процедур: `/new-feature`, `/new-spec`, `/new-design`, `/verify`, `/pr`… |
| Макеты | `docs/design/<фича>/variant-a.html`, `variant-b.html` | HTML-превью двух вариантов интерфейса (двойной клик в браузере); описание — в `docs/design/README.md` |
| Хуки | `.claude/hooks/*.mjs` + `.claude/settings.json` | Скрипты, которые харнесс запускает **при событии** (гарантии) |
| Права | `.claude/settings.json` | Что можно без вопросов, что запрещено |
| MCP | `.mcp.json` | Внешние инструменты: GitHub, Context7, Playwright |
| Личные настройки | `.claude/settings.local.json` (в `.gitignore`) | Только для вас, в git не попадает |

## Команды (скиллы)

`/new-feature` — фича от идеи до PR (4 обязательные паузы-GATE) · `/new-spec` — спека, которую вы утверждаете сами · `/new-design` — два макета на выбор · `/new-adr` — архитектурное решение · `/db-migration` — миграция БД · `/verify` — сборка, тесты, lint · `/review` — ревью diff · `/sync-docs` — сверка docs с кодом · `/pr` — pull request.

Описание каждой команды, аргументы и примеры — [COMMANDS.md, раздел 6](COMMANDS.md#6-список-команд-этого-проекта).

**Как согласуется фича** (спека → макет → план → PR, ничего не строится до вашего «утверждаю») — [GUIDE.md, раздел 10.0](GUIDE.md#100-как-согласуется-фича-от-идеи-до-утверждённой-спеки-и-макета).

> **Внимание.** Имена `/verify` и `/review` совпадают со встроенными командами Claude Code. Что выбирается при вызове, требует проверки. См. [COMMANDS.md, раздел 7](COMMANDS.md#7-предупреждение-о-конфликте-имён).

## Что гарантируют хуки

| Хук | Событие | Что делает |
|---|---|---|
| `session-start` | старт сессии | сообщает ветку, число незакоммиченных записей, последние коммиты и ключевые правила |
| `guard-bash` | перед Bash | блокирует force-push, push и commit в `main`, `--no-verify`, `rm -rf` корня или домашней папки, чтение `.env`; спрашивает перед `reset --hard`, `checkout --`, `restore` и `dotnet ef database update/drop` |
| `guard-files` | перед Edit/Write/MultiEdit | запрещает правку миграций и снимка модели, запись в `.env*`, `*.pem`, `*.sql`, `*.dump`; ищет секреты в записываемом тексте |
| `stop-check` | перед завершением ответа | при изменениях в `backend/` и `frontend/` проверяет сборку (`dotnet build`, `tsc --noEmit`) и один раз напоминает про документацию |

Подробно — [GUIDE.md, раздел 3](GUIDE.md#3-hooks-автоматические-проверки).

## Правила игры

1. Работаем в ветке (`feat/…`, `fix/…`, `chore/…`, `docs/…`). Коммиты — Conventional Commits. В `main` — через PR.
2. Секреты не коммитим. Хуки подстрахуют, но это не повод расслабляться.
3. Новая логика — с тестами. «Готово» = `/verify` зелёный (запуск, а не слова).
4. Меняется поведение — обновляем спеку в `docs/specs/`. Меняется архитектура — пишем ADR в `docs/adr/`.
5. Изменения `.claude/` и `CLAUDE.md` — через PR. Владельцы — в `.github/CODEOWNERS`.

## Как расширять

Новый агент, скилл, хук, правило и MCP-сервер — [GUIDE.md, раздел 12](GUIDE.md#12-шпаргалка-и-как-расширять-конфигурацию). После изменений скиллов — `/reload-skills`. Для агентов и хуков надёжнее новая сессия (**(не проверено)** в вашей версии).

Документы и файлы не во всём совпадают: тесты фронтенда, `.env.example`, `docs/README.md`, `CHANGELOG.md` и другие. Полный список — [GUIDE.md, раздел 13](GUIDE.md#13-известные-расхождения-на-дату-написания).
