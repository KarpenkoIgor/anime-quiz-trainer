# Claude в этом проекте — карта на одну страницу

Подробности и примеры: [GUIDE.md](GUIDE.md). Здесь — «что где лежит и кого звать».

## Что где лежит

| Сущность | Файлы | Что это |
|---|---|---|
| Память проекта | `CLAUDE.md`, `backend/CLAUDE.md`, `frontend/AGENTS.md` | Правила и контекст, которые Claude читает сам |
| Правила по путям | `.claude/rules/*.md` | Подгружаются, когда Claude работает с подходящими файлами |
| Агенты | `.claude/agents/*.md` | 13 «специалистов» со своим контекстом, инструментами и моделью |
| Скиллы (команды) | `.claude/skills/*/SKILL.md` | Повторяемые процедуры: `/new-feature`, `/verify`, `/pr`… |
| Хуки | `.claude/hooks/*.mjs` + `.claude/settings.json` | Скрипты, которые харнесс запускает **всегда** (гарантии) |
| Права | `.claude/settings.json` | Что можно без вопросов, что запрещено |
| MCP | `.mcp.json` | Внешние инструменты: GitHub, Context7, Playwright |
| Личные настройки | `.claude/settings.local.json` (в `.gitignore`) | Только для вас |

| Ситуация | Агент |
|---|---|
| Идея → требования, user stories, задачи | `product-analyst` |
| Механики, рейтинг/ладдер, баланс | `game-designer` |
| Типы вопросов, дистракторы, сложность | `quiz-designer` |
| Качество каталога, названия, дубликаты, источники | `anime-content-curator` |
| Как устроить систему, границы слоёв, ADR | `architect` |
| Написать серверный код | `backend-dev` |
| Написать UI / сторы | `frontend-dev` |
| Схема БД, миграции, медленные запросы | `db-engineer` |
| Тесты, тест-план, воспроизведение бага | `qa-engineer` |
| Проверить diff (только чтение) | `code-reviewer` |

## Команды (скиллы)

`/new-feature` — фича от идеи до PR · `/new-spec` — спека · `/new-adr` — архитектурное решение · `/db-migration` — миграция БД · `/verify` — сборка/тесты/lint · `/review` — ревью diff · `/sync-docs` — сверка docs с кодом · `/pr` — pull request.

## Что гарантируют хуки

| Хук | Событие | Что делает |
|---|---|---|
| `session-start` | старт сессии | сообщает ветку, статус git, ключевые правила |
| `guard-bash` | перед Bash | блокирует force-push, push/commit в `main`, `--no-verify`, `rm -rf /`, чтение `.env`; спрашивает перед `reset --hard` и `dotnet ef database update` |
| `guard-files` | перед Edit/Write | запрещает правку миграций, `.env`, `*.sql`, ищет секреты в записываемом тексте |
| `stop-check` | перед завершением ответа | проверяет сборку (`dotnet build`, `tsc`), один раз напоминает про документацию |

## Правила игры

1. Работаем в ветке (`feat/…`, `fix/…`, `chore/…`, `docs/…`), коммиты — Conventional Commits, в `main` — через PR.
2. Секреты не коммитим. Хуки подстрахуют, но это не повод расслабляться.
3. Новая логика — с тестами; «готово» = `/verify` зелёный.
4. Меняется поведение → обновляем спеку; меняется архитектура → пишем ADR.

## Как расширять

Новый агент — файл в `.claude/agents/` (формат см. в GUIDE, раздел 4). Новый скилл — папка `.claude/skills/<имя>/SKILL.md`. Новый хук — скрипт в `.claude/hooks/` + запись в `.claude/settings.json` + проверка на примерах событий. После изменения конфигов перезапустите сессию Claude Code.
